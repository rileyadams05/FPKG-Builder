# FPKG Builder

FPKG Builder is a lightweight Linux desktop application for turning compatible PS4 game dumps made with [Itemzflow](https://github.com/LightningMods/Itemzflow) into fPKG files. It is designed to finish the packaging step on a PS4 that is already set up to run Linux and Itemzflow, without sending a large dump to a separate Windows PC for packaging.

**Itemzflow handles dumping. FPKG Builder handles packaging.** FPKG Builder is an independent companion; it does not replace Itemzflow, install Linux, jailbreak a console, or reproduce every feature of [LibOrbisPkg](https://github.com/maxton/LibOrbisPkg).

## Who it is for

FPKG Builder is for PS4 Linux users who already have a compatible Linux installation and use Itemzflow to dump their own game content. It can reduce the need for a PC after console setup by building the package where the dump already lives. A computer may still be needed temporarily to prepare installation media, configure payloads, or complete other initial PS4/Linux setup steps. This application does not perform those steps.

## How it works

1. Drop a game dump folder or GP4 project into the application, browse for it, enter its Linux path, or choose an accessible dump discovered from Itemzflow's `Dumper_Path` setting.
2. FPKG Builder checks the dump metadata and referenced files. Orbis paths are resolved against the selected Linux dump when possible; a PS4 OS path is never assumed to be mounted in Linux.
3. A valid GP4 generated by Itemzflow is reused without rewriting it. If no usable GP4 exists, a project is generated in memory as a fallback.
4. Choose an output folder. The application checks available space and keeps package output outside the source dump.
5. The bundled .NET 8 helper uses LibOrbisPkg to build the fPKG. The interface displays measured progress for supported stages, processed bytes and measured throughput. Remaining time is an estimate; stages without measurable totals stay indeterminate.
6. LibOrbisPkg validation runs after packaging. The app reports the output path, size and validation result. Validation does not prove that a package will install or run on a PS4.

The source dump and an existing GP4 are left unchanged. Game files are processed locally and are not uploaded to a website or remote service. There is no separate Build or Edit button; processing starts when valid input is selected.

## Scope and status

The initial compatibility target is **base-game dumps**. Patch and DLC compatibility has not been verified. This is version **0.1.0**, an early testing version. Synthetic fixtures, the packaged Linux application and Linux package formats have been exercised in controlled environments. Testing on PS4 hardware with a real Itemzflow dump is still pending.

The local project contains verified Linux `.deb`, `.rpm`, and `.pkg.tar.zst` installers under `release-artifacts`, but these build artifacts are excluded from this source repository. No GitHub Release has been published for this repository yet. Public distribution will be a separate step after release approval. Windows packaging is outside the current scope.

## Linux packages

The application is built from one codebase for x86-64 Linux:

| Format | Intended distributions |
| --- | --- |
| `.deb` | Linux Mint, Ubuntu, Debian |
| `.pkg.tar.zst` | Arch Linux, Manjaro |
| `.rpm` | Fedora and compatible distributions |

Tauri uses the system WebKitGTK and GTK runtime on Linux. Install the matching package with its distribution's package manager. The PS4 Linux Mint test checklist is in [`docs/ps4-linux-mint-test.md`](docs/ps4-linux-mint-test.md); do not treat Linux desktop smoke tests as PS4 hardware validation.

## Build and development

The repository includes the Tauri 2 frontend, Rust desktop shell, .NET 8 packaging helper, and the modified LibOrbisPkg source. A native x86-64 Linux build environment is required for the Linux installers.

Prerequisites:

- Node.js 22 and npm
- Rust stable toolchain
- .NET 8 SDK
- Tauri 2 Linux development dependencies (GTK 3, WebKitGTK 4.1, and distribution build tools)

Install JavaScript dependencies, run the frontend tests and build the helper:

```sh
npm ci
npm test
npm run build
dotnet build src/Vortex.Engine.Poc/Vortex.Engine.Poc.csproj -c Release
```

For Linux package builds, publish the helper as a self-contained `linux-x64` application into `src-tauri/resources/engine`, name the published executable `vortex-engine`, bundle the required notices and dependency licences, then run:

```sh
npm run tauri:build -- --bundles deb,rpm
```

The Arch workflow packages the same Tauri application binary and helper with `packaging/PKGBUILD`. GitHub Actions workflows under [`.github/workflows`](.github/workflows) run fixture checks, build Linux packages, smoke-launch them in representative environments, and prepare checksummed artifacts. The workflows do not publish a release or deploy a website.
