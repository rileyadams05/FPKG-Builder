# FPKG Builder v0.1.2

This release updates the PS4 Linux packaging workflow after the first real-console test of v0.1.1 exposed a PlayGo chunk-hash allocation failure.

## Changes

- Corrected LibOrbisPkg's PlayGo chunk-hash reservation so it accounts for the final aligned PKG body size.
- Requires an external SSD or HDD for the Itemzflow dump, large temporary data and the finished package. The application creates an `FPKG` folder beside the selected `Itemzflow` folder and refuses to build on the Linux system drive.
- Detects a single base-game dump and its matching `-patch` folder, then builds one combined `.pkg`. If no update is present, the user can continue with the base game alone.
- Supports a user-supplied `Update.pkg` only when its fake-package metadata and inner PFS are readable by LibOrbisPkg. Encrypted packages that cannot be read are rejected; the application does not bypass package encryption.
- Ignores Itemzflow logs and `.complete` markers and leaves the source dump, GP4 projects and supplied update package untouched.
- Excludes DLC from this application.

## Verification

GitHub Actions passed the PlayGo allocation regression cases, controlled GP4 generation and reuse, base-game packaging, matching Itemzflow update merging, `Update.pkg` extraction and merging, package validation, and source-preservation checks. The Debian and Fedora packages installed and launched in automated Linux smoke environments.

**Testing on the PS4's Linux Mint installation with a real Itemzflow dump is still required.** Automated package validation and desktop Linux smoke tests do not establish PS4 installation or gameplay compatibility.

## Installers

- `FPKG-Builder-0.1.2-linux-x64.deb` — Linux Mint, Ubuntu and Debian
- `FPKG-Builder-0.1.2-linux-x64.rpm` — Fedora and compatible RPM-based distributions

The packages use the same application codebase. LibOrbisPkg and other third-party notices are included in the source archive and application resources.
